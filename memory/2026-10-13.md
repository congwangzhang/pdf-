## review-classifier / 综述文献分类工具：推倒重建

上午第一版（AI 往返式：索引发给 AI → 导入 outline/assignments）被用户否定："非常不满意，清空现有的架构"。

**新需求（用户原话的 5 步）**：①选择文献文件夹 ②提取每篇综述章节骨架 ③确定要写的综述骨架 ④查看框架/分类框架并手工调整 ⑤归档 PDF。用户是代码小白，要求可执行文件容易操作。

**新架构**（旧的 wizard.py/scripts/一键运行* 全部删除）：
```
综述文献分类工具/
├── 启动工具.bat   ← Windows 双击
├── 启动工具.sh
├── app.py         ← tkinter 图形界面，5 个标签页 = 5 步，全程无代码
├── core.py        ← 核心逻辑（提取/骨架/分类/归档，可脚本化调用）
└── README.md      ← 小白图文说明
```
- 关键设计：全自动本地闭环，不再需要"发文件给 AI"环节；自动分类用关键词匹配（标题×3、摘要×2、骨架×1），第④步界面手工微调
- 进度自动存 `project.json`；产物：章节骨架汇总.md / outline.json / assignments.json / 归档结果(分类报告.md)
- 骨架编辑支持：加子/同级标题、编辑（含分类提示词）、删除、上下移、升降级、从"文献常见章节"一键导入
- 归档命名可选 `id-heading` 或纯标题名

**测试**：core 全链路实测通过（3 篇合成 PDF）；GUI 因沙箱无 python3-tk 用 MagicMock 桩做了冒烟测试（构建+骨架编辑+分类+手动调整+归档全走通）。真实 tkinter 视觉效果未经验证——用户首次运行若报错要优先怀疑界面层。

**交付**：工作区 `综述文献分类工具/`（含 zip）、技能目录 `~/.openclaw/skills/review-classifier/`（SKILL.md 薄壳+工具本体）、`review-classifier.skill` 打包件。免疫衰老项目数据仍在 `免疫衰老_框架与分类/`。

**10:28 用户反馈迭代（第②步提取质量 + AI 按钮）**：
- 提取引擎升级为三级：**pdfminer.six（字体感知，最准）> pdftotext > pypdf**；骨架识别用「字号+编号」双通道，无编号大字号标题也能抓层级

- 列表 ✅/⚠️ 质量标记 + 「只显示未提取到骨架的」筛选 + 统计行
- 测试：5 个合成 PDF（编号变体/无编号大字号/多页页眉/扫描版空文本）全符合预期；AI 链路（生成→解析→合并）冒烟通过

## 教训
- 用户是代码小白 → 交付"双击就能用的界面"，不要让 ta 操作命令行/JSON/发文件给 AI
- 用户说"重新规划/清空"时就是全推倒，别在旧架构上缝补
- **Windows .bat 必须 GBK + CRLF**：UTF-8+LF 的批处理在 cmd 里直接闪退无反应（用户实测踩坑）；写完用 python 转码；启动脚本要全程可见输出 + 写启动日志 + 检测 Python/tkinter
- GUI 工具加崩溃兜底：main() 裹 try/except 写错误日志.txt + 弹窗告知
